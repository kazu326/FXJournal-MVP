# Deploy Skill

Description: このプロジェクトのデプロイ手順を定義します。「デプロイして」と言われたらこの手順を厳守してください。

## Triggers
- デプロイして
- 本番環境に反映して
- deploy

## 前提

デプロイは **`main` への `git push` で Vercel が自動実行**します。
`vercel` CLI を手で叩く必要はありません。つまり **push した時点で本番に出ます。**
push を「まだ本番ではない」と扱わないこと。

## Actions

### 1. マイグレーションの適用状況を確認（最重要）

**コードより先に DB を適用する。** 順序を逆にすると、存在しない関数やテーブルを
呼ぶコードが本番に出て、画面がエラーになる。

- `supabase/migrations/` に未適用のものがないか確認する。
- 未適用があれば、先に適用し、適用結果を検証してから次に進む。
- 権限（RLS / `is_staff()`）に関わるマイグレーションを適用したときは、
  デプロイ前に必ず対象ユーザーで `is_staff()` が `true` を返すことを確認する。
  ここを飛ばすと管理者が管理画面のデータを読めなくなる。

### 2. 検証

以下を実行し、**すべて通ること**を確認する。

| コマンド | 期待 |
| --- | --- |
| `npx tsc -b` | エラーなし |
| `npm test` | 全件 PASS |
| `npm run e2e` | 全件 PASS |
| `npm run governance:check` | `Governance checks passed.` |
| `npm run build` | 成功（チャンクサイズ警告は既存のもの、無視可） |

**`npm run lint` について:** 現状リポジトリ全体で既存エラーが 26 件ある（`no-explicit-any` 等）。
そのため「エラーゼロ」を条件にすると常に停止する。判定は
**「自分の変更したファイルで新たなエラーが増えていないか」** で行うこと。

```bash
npx eslint <変更したファイル>
```

既存エラーの解消は別タスクとして扱う。デプロイのブロッカーにしない。

### 3. デプロイ

```bash
git push origin main
```

Vercel が自動でビルド・デプロイする。1〜2分程度かかる。

### 4. デプロイ後の確認

- 本番 URL: https://fx-journal-mvp.vercel.app/
- 変更した画面を実際に開く。
- **ブラウザのコンソールを必ず確認する。** ビルドが通ってもランタイムで落ちることがある。
  実例: `supabase.rpc` をメソッドから切り離して変数に代入したことで
  `Cannot read properties of undefined (reading 'rest')` が発生し、
  ユニットテストも E2E も通過したまま本番だけが壊れた。
- 管理画面を変更した場合は、ユーザー一覧に全メンバーが表示されることまで確認する。
