# FX Journal ウェブ版アプリ（PC版）分析機能 基本方針

**ステータス：MVP V1 完了（2026-07-30）**

## この文書の対象

本書はFX Journalプロジェクト全体を「分析プラットフォーム」と定義するものではない。PCで提供するウェブ版アプリの分析機能に限定した基本方針である。

FX Journal全体は、自己管理と自己責任を支援する学習・記録環境である。スマホアプリ版とウェブ版アプリは、次の異なる役割を担う。

| 提供面 | 主な役割 | 課金方針 |
| --- | --- | --- |
| スマホアプリ版 | 毎日の取引前・取引後・見送り記録を通じて習慣化を身につける | 現段階では完全無料を予定する |
| ウェブ版アプリ（PC版） | 習慣化できているかを分析し、判断、情報、時間の使い方を客観視する | 基本分析は無料で提供し、将来の高度分析を有料枠として検討する |

## プロジェクト全体の背景

プロジェクトの背景には、トレーダーが継続的に自己管理を学び、実践できる環境が不足し、判断や行動を振り返れないまま市場から離れる人が多いという課題認識がある。FX Journalは利益を約束するのではなく、記録、学習、客観視を通じて、ユーザー自身が判断と行動に責任を持てる状態を支援する。

金融庁も、詳細なルールを適用する「ルール・ベースの監督」と、主要な原則に沿った自主的な取組みを促す「プリンシプル・ベースの監督」を最適に組み合わせる考え方を示している。プロジェクトは規制そのものを利用者へ適用するものではないが、原則を理解し、自ら考えて判断できる金融リテラシーを重視する方向と整合する。

参考：[金融規制の質的向上（ベター・レギュレーション）｜金融庁](https://www.fsa.go.jp/policy/br-pillar4.html)

## 目的

ウェブ版アプリは、相場の答えを提示するサービスではなく、スマホアプリ版で蓄積した本人の記録を集計し、判断根拠・ルール遵守・見送り・記録習慣を客観視する分析サービスとして提供する。分析を明確にし、迷いとトレードに関わる無駄な時間を減らし、ユーザーが精神的・時間的な余裕を持てる状態を目指す。

利益、勝率、取引回数の増加はユーザー個人の目標になり得るが、アプリが約束する成果にはしない。

アプリが担う順序は次のとおりとする。

1. 観測するきっかけを示す
2. ユーザーが根拠とリスクを確認する
3. 判断内容を記録する
4. 記録を期間集計して振り返る

## ウェブ版プロダクトの価値

ウェブ版アプリが提供する価値は次の3点とする。

1. スマホアプリ版で続けた記録から、無駄な時間、不足している情報、不足を埋めようとして過剰に追いかけている箇所を見えるようにする
2. 「分析とは何を確認することか」を整理し、毎日記録する価値と、記録を振り返る価値を理解できるようにする
3. 分析の考え方を無料枠で学べる環境を提供し、理解したユーザーが、より深く・速く・継続的に分析する価値を選べるようにする

## 表示と判断の原則

- 画面は件数、割合、期間、回答状況など、記録から説明できる事実を表示する
- 「曜日を変えるべき」「この時間帯で取引すべき」のような行動の断定をしない
- データが少ない場合は結論を作らず、「データ不足」と必要な記録量を示す
- 一般的な傾向と本人の記録を区別し、推測は推測として明示する
- 最終判断はユーザーに残し、アプリは整理と客観視を支援する
- 利益、勝率、取引回数、アプリ滞在時間の増加を成功指標にしない

## 無料枠と有料枠

スマホアプリ版は、現段階では完全無料で提供する予定とする。習慣化に必要な取引前・取引後・見送り記録や学習導線へ、有料枠を設けない。

ウェブ版アプリの無料枠は、自己分析、習慣化の客観視、分析の基本理解に必要な機能を成立させる。分析の意味が分からない状態で有料機能を提示しない。

有料枠はウェブ版アプリの分析機能へ実装する。「勝ちやすくする機能」ではなく、理解した分析をより深く・速く・継続的に行い、FXに関わる時間を減らしながら同じ判断・振り返りを行いやすくする機能とする。長期比較、詳細な時間帯分析、分析結果の保存、自動集計、読み取り専用連携など、分析期間・比較・保存・自動化・連携範囲を拡張する。無料枠で成立している分析の基本理解とCSV保存を後から狭めない。

## 計測して育てる方針

プロダクト価値とUI/UXは、実データとユーザーの声を時間をかけて確認しながら育てる。機能追加より先に、何が使われ、どこで迷い、どの価値が伝わっているかを把握する。

計測候補は次のとおりとする。

- 分析画面への7日・30日再訪
- 期間切替、CSV保存、AI振り返り用指示文コピーの利用
- 取引前・取引後・見送り記録の継続とデータ充足度
- エラー、途中離脱、操作に迷った箇所
- 「確認点が明確になった」「迷う時間が減った」「余裕が生まれた」という本人評価
- 管理者へ届く相談内容、UI/UX要望、分析機能への要望

計測イベントへ自由記述、CSV内容、個人の損益をそのまま送らない。他ユーザーとの比較は、同意、匿名化、十分な母数、表示目的が整うまで実装しない。比較する場合も順位付けではなく、「時間をかけなくてもよい可能性がある箇所」を客観視する補助情報として扱う。

## 用語

「シグナル」ではなく「分析トリガー」を使用する。

分析トリガーは売買判断ではなく、追加分析を開始するための観測情報を意味する。将来実装する場合は、検出ロジック、使用データ、対象期間・時間足、検出日時、有効期限、追加確認項目を表示する。

## 現在提供する機能

- 本人の記録の期間集計
- 分析用CSV
- 記録完了率・ルール遵守・見送りなどの行動分析
- AI振り返り用のプロンプト

## 将来計画にのみ含める機能

- 根拠を説明できる分析トリガー
- MT5履歴の読み取り専用取り込み
- 外部AIとの明示的な連携
- 読み取り専用MCPと配布用スキル

これらはMVP V1には実装しない。

## MVP V1：行動インサイト

第二弾では、新しい外部データや市場予測を追加せず、本人の既存記録から次の情報を決定的なルールで集計する。

- 計画内取引・ルール外・見送りの内訳
- 実取引・練習の件数
- 事前チェック、取引後記録、ルール振り返り、想定内確認のデータ充足度
- 曜日別の記録件数と記録日数
- 見送り、未完了、回答不足などを事実ベースで示す行動インサイト

取引後記録の完了率は、見送りを未完了として扱わず、取引記録だけを母数にする。行動インサイトは損益の評価、将来予測、売買推奨を行わず、件数と回答状況から説明できる内容だけを表示する。

分析トリガー、市場データ連携、期間比較は、この段階には含めない。

## MVP V1の完了条件

実装上の第一段階と第二段階を、MVP V1の公開初期版としてまとめる。次を満たした状態で完了とする。

- PC版 `/analysis` で30日・90日・全期間を選択できる
- 記録数、取引／見送り、取引後記録率、ルール遵守率を確認できる
- 記録の内訳、データ充足度、曜日別件数、事実ベースの行動インサイトを確認できる
- 見送りを取引後記録の未完了として扱わない
- 本人の記録だけをページング取得し、1000件を超えても欠落させない
- 個人IDと管理者用情報を含まないCSV Schema v1を保存できる
- 自由記述は初期状態で除外し、明示的に選択した場合だけ含める
- CSV数式注入を防ぎ、AIへデータを自動送信しない
- 売買推奨を避けるAI振り返り用指示文をコピーできる
- モバイルではPC利用の案内を表示し、既存アプリの導線を壊さない
- Build、単体テスト、E2E、対象Lint、ガバナンスチェックが成功する

実データが十分に蓄積した後の具体的な傾向分析は、MVP V1の完了条件に含めない。現時点では機能の土台と安全境界が成立していることを完了条件とする。

## V2〜V5ロードマップ

### V2：利用計測と実データ検証

まずMVP V1を実際のユーザーに利用してもらい、管理者集計と本人評価から価値・摩擦・不足を確認する。

- 分析画面の再訪、期間切替、CSV保存、指示文コピーを計測できるイベント設計
- 自由記述やCSV本文を含めない計測データ契約
- 実データでの曜日別表示、データ充足度、空状態、少数データ表示の検証
- 管理者が個人の損益ではなく、継続・利用・困りごとを把握できる集計
- アンケートと相談内容からUI/UX改善候補を整理する運用

V2の実装は、計測目的、保存期間、閲覧権限、同意表示を決めてから開始する。

### V3：分析の深掘りと有料枠

実データから需要が確認できた分析だけを追加する。

- 前期間との比較、長期推移、時間帯・曜日別の事実表示
- 不足しているデータと、過剰に時間をかけている可能性がある箇所の整理
- 分析結果の保存、比較、再利用
- 匿名化された比較情報。ただし同意と十分な母数を必須とする
- 無料枠の理解を損なわない有料機能境界の検証

有料枠のKPIは利益や勝率ではなく、分析時間の短縮、確認点の明確さ、継続利用、本人が感じる余裕とする。

### V4：MT5読み取り専用連携

- MT5の取引履歴と必要な相場データを読み取り専用で取り込む
- 日時、通貨ペアなどからアプリ記録との対応候補を示す
- 自動一致と手動確認を分け、一致の確度と不明点を表示する
- 記録した判断と実際の履歴を照合し、入力差や振り返り不足を客観視する
- ログイン情報、注文権限、自動売買機能を保持しない

実装前に入力形式、照合精度、未一致時の扱い、データ削除、再取り込みを定義する。

### V5：AI・MCP・スキル連携

- ユーザーが明示的に選択した記録と集計だけを外部AIへ渡す
- AI出力は事実、推測、データ不足を分離する
- CSV Schemaのバージョンを維持し、プロンプトインジェクションを分析対象データとして隔離する
- MCPは記録、集計、分析トリガーと根拠の読み取り専用にする
- 注文、ポジション変更、売買方向を生成するツールを同居させない
- 同じ安全境界を持つ配布用スキルを用意する

AI回答から外部操作へ直結する機能は計画に含めない。

## 提供しない機能

- 買い・売りの指示
- エントリー、利確、損切り価格の推奨
- 自動注文
- EAの提供・推奨
- AI回答から注文を実行する連携
- 利益を保証または期待させる評価

無料・有料のどちらでも、この境界は変更しない。

## CSV Schema v1

分析CSVは、将来のAI、MT5、MCP連携に利用する最初のデータ契約である。

- 列名と順序を固定する
- 各行に `schema_version` を含める
- `record_id` を維持する
- 日時はISO 8601形式とする
- 真偽値は `true` / `false` とする
- 個人ID、メール、Discord情報、講師メモを含めない
- 自由記述はユーザーが明示的に選択した場合のみ含める
- 表計算ソフトで数式として解釈され得る文字列を無害化する

CSVの変更は、既存列の意味を変更せず、新しいSchemaバージョンとして追加する。

## 将来のMT5・MCP境界

MT5連携は履歴と相場データの読み取りに限定する。ログイン情報や注文権限を保存しない。

MCPは記録、集計、分析トリガーと根拠の読み取りのみを提供する。注文、ポジション変更、売買方向の生成に使用できるツールを同居させない。

## 公開前確認

個別性の高い有料分析や市場分析トリガーを公開する前に、具体的な入力、画面、出力例を用意し、法務・規制上の確認を行う。免責文だけで境界を担保せず、出力構造と技術権限によって制限する。

各バージョンは、実データ、ユーザー要望、UI/UX上の摩擦、安全境界を確認してから着手する。ロードマップは実装の約束ではなく、基本方針を守りながら次の判断を行うための順序として扱う。
