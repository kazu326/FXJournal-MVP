# メッセージ・ケアハブ

## 目的

メッセージページを、単なるDM一覧から次の3機能へ分離する。

- 全ユーザー向けの一方向お知らせ
- 月1回・5問の行動チェックインと根拠付きフィードバック
- ユーザーが必要なときに開始できる、無償の習慣サポート

評価対象は利益や勝敗ではなく、記録、ルール遵守、見送り、次の行動の明確さである。個別の通貨、価格、売買時点、ロットを推奨する機能にはしない。

## 利用者画面

- 未回答時は「今月の行動チェックイン」を表示する。
- 回答は各設問固有の1〜5段階とし、該当しない可能性がある設問だけ「今月は該当なし」を許可する。
- 自動公開できるフィードバックと、担当者確認後に公開するフィードバックを分ける。
- 根拠カードでは、研究の要約と同時に対象範囲・限界・出典を表示する。
- 習慣サポートはユーザー起点で開始し、過去のDMは読み取り専用で残す。

## 管理画面

`/admin/messages` を次の3タブに分ける。

- お知らせ: 返信を受け付けない全体通知
- 相談対応: ユーザー起点の相談への返信と解決
- 月次レビュー: 組織別の回答状況と、公開前フィードバックの確認

組織スタッフの管理画面アクセスはメッセージ管理だけに限定する。組織データはRLSで所属範囲に絞り、回答者が5人未満の組織では平均値を返さない。

## 投資助言防止

運営発信は次の層で保護する。

1. 管理画面に、回答できる範囲を常時表示する。
2. フロントエンドで、具体的な売買時点、通貨ペアの方向、損切り・利確水準、ロット推奨を検出して送信を止める。
3. DB関数でもスタッフ返信を同じ範囲で拒否する。
4. 一斉お知らせはDBトリガーでも検査する。
5. Push通知本文と宛先はクライアントから受け取らず、認証済み送信者と保存済みレコードから再構成する。

この検査は法的判断を代替しない。境界表現やテンプレートの追加時は、運用責任者によるレビューを行う。

## フィードバック判定

判定は再現可能なルールで行い、生成AIによる自動診断は行わない。

優先順位は次のとおり。

1. 相談希望
2. 比較できる記録がない
3. いずれかの回答が2以下
4. 回答平均が4以上
5. 経過確認

利益額、勝率、含み損益は判定材料にしない。根拠カードは版管理し、FXの成績へ直接一般化できないことを明記する。

## Supabase反映順

1. `20260729125543_create_message_care_hub.sql` を適用する。
2. `push-notification` と `create-monthly-checkins` をデプロイする。
3. `create-monthly-checkins` 用に十分な長さの `CRON_SECRET` を設定する。
4. 月初に同Functionへ `POST` し、`x-cron-secret` を付けるスケジュールを設定する。

スケジュール設定前でも、利用者がメッセージページを開いた際に当月割当を冪等作成するため、機能は停止しない。

## 採用した根拠

- 進捗モニタリング: Harkin et al. (2016), [Psychological Bulletin / PubMed](https://pubmed.ncbi.nlm.nih.gov/26479070/)
- If–Then計画: Gollwitzer & Sheeran (2006), [Advances in Experimental Social Psychology](https://doi.org/10.1016/S0065-2601(06)38002-1)
- 損失後のブレークイーブン効果: Thaler & Johnson (1990), [Management Science](https://doi.org/10.1287/mnsc.36.6.643)

各研究はアプリ内の行動支援を考える背景であり、FXの利益改善や個人の状態を直接証明・診断するものではない。
